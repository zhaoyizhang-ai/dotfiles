# Ideation Technique: Analogy Transfer

## Objective
Generate ideas by abstracting the seed problem into a domain-agnostic structure, finding analogous problems in distant domains, and mapping their solutions back.

## Process

### Step 1: Structural Abstraction
Restate the seed problem as a domain-independent structural description.
- Strip away domain-specific terminology
- Focus on the underlying pattern: input → transformation → desired output
- Example: "finding an optimal path through a high-dimensional constrained space" instead of "robot motion planning"

### Step 2: Distant Domain Search
For each of the following 5 domains, identify a structurally analogous problem and its known solutions:

1. **Biological / Natural Systems** — Evolution, ecosystems, cellular mechanisms
2. **Economic / Market Mechanisms** — Pricing, auctions, supply chains
3. **Social / Organizational Behavior** — Governance, collaboration, conflict resolution
4. **Physical / Chemical Processes** — Thermodynamics, crystallization, phase transitions
5. **Game / Art / Design** — Game mechanics, narrative structures, architectural design

### Step 3: Solution Mapping
For each domain analogy:
- Describe the source solution
- Map it back to the original problem domain
- Generate one or more concrete ideas

## Expected Output
- A table with columns: #, Source Domain, Source Problem, Source Solution, Mapped Idea, Direction Tag
- Minimum 8 ideas across at least 3 different source domains
- Round statistics: idea count, new directions, duplication rate
