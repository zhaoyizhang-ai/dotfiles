## Transformation Operators

### S — Substitute
What components, materials, methods, or assumptions can be replaced?
- What if we substitute [component A] with [alternative]?
- What if a different algorithm/architecture/process were used?

### C — Combine
What if two existing approaches were merged?
- What if we combined [approach A] with [approach B]?
- What hybrid architectures or workflows would emerge?

### A — Adapt
What can be borrowed from other domains?
- What parallel problem exists in [biology / economics / physics / design]?
- How would that domain's solution adapt to our context?

### M — Modify / Magnify
What if we changed the scale, degree, or parameters?
- What if the input were 10x larger / smaller?
- What if the constraint were relaxed by N%?

### P — Put to Other Use
What if the solution were applied to a completely different scenario?
- What other problems could the same mechanism solve?
- What unexpected applications would emerge?

### E — Eliminate
What if a supposedly necessary element were removed?
- What if we didn't need [component X]?
- What is the minimal viable version?

### R — Reverse / Rearrange
What if the order or structure were inverted?
- What if the process ran backwards?
- What if the roles of [A] and [B] were swapped?

## Expected Output
- A table of ideas with columns: #, Idea Summary, SCAMPER Operator, Direction Tag
- Minimum 8 ideas across at least 4 different operators
- Round statistics: idea count, new directions, duplication rate
