在 Obsidian 笔记中写入内容、整理格式、排版优化。

## 触发场景

- 写入新内容：用户提问、粘贴 AI 回答 → 整理成笔记风格写入
- 整理已有内容：用户说"整理一下""格式化""排版" → 只改格式，不改内容
- 两者兼有：用户粘贴内容并要求整理到指定位置

根据用户需求判断是哪种，不要默认只做写入。

## 调用格式

用法：`/obsidian-note-maker <文件名> <问题 或 粘贴内容 或 整理指令>`

例：
- `/obsidian-note-maker 概统A.md 解释什么是充分统计量`
- `/obsidian-note-maker Research/dreamdojo.md [粘贴 GPT 的回答]`
- `/obsidian-note-maker 程设 py技巧.md 整理最后那部分的格式`
- `/obsidian-note-maker AI引.md 3.2节末尾 [内容]`（指定位置时在文件名后说明）

如果用户没有提供文件名，立即提示：
> 请告诉我：`/obsidian-note-maker <文件名> <内容或指令>`

## az 的笔记风格规范

参考笔记（3月14日后的风格）：
- 短句、关键词导向，不写废话
- 有 insight 时写「理解：」或「insight：」开头
- 数学公式用 $...$ 或 $$...$$（单独成行居中）
- 引用其他笔记用 [[文件名]]
- 不加多余标题，内容直接写，融入笔记层级
- 语气口语化、直接，用「说白了」「本质是」等

### 加粗使用

- 默认不加粗，保持简洁
- 需要强调结构（如小标题、分类名称）时可以用加粗

### 列表选择

- 无序列表 `-`：适合零散要点、并列特征、没有先后关系的内容
- 有序列表 `1. 2. 3.`：适合有步骤顺序、分类枚举、流程说明的内容
- 根据内容语义选择，不要无脑全用无序列表

## 执行步骤

1. **解析参数**：提取文件名和内容/问题/指令。文件名可以是相对路径（相对于 `__HOME__/Desktop/Notes/`）或仅文件名（在根目录搜索）。

2. **检查文件**：若文件不存在，停止并提示用户确认路径，不自动创建。

3. **编辑前 push**：在修改文件之前，执行以下命令备份当前状态：
   ```
   git -C __HOME__/Desktop/Notes add -A && git -C __HOME__/Desktop/Notes commit -m "backup before obsidian-note-maker edit" && git -C __HOME__/Desktop/Notes push
   ```
   如果没有变更需要 commit，直接跳过 add/commit，只 push。

4. **判断任务类型**：
   - **纯整理格式**（用户说"整理""格式化""排版"）：只改格式（标题层级、列表、代码块、缩进等），不改、不删、不补充内容
   - **写入新内容**（用户提问或粘贴内容）：整理成笔记风格后写入
   - **两者兼有**：先整理已有格式，再写入新内容

5. **写入/修改文件**：
   - 默认追加到文件末尾
   - 如果用户指定了位置（如「3.2节末尾」「第一行后面」），找到对应位置插入
   - 写入前后各空一行与原内容分隔

6. **完成**：告知用户做了什么改动，显示改动的前几行供确认。
